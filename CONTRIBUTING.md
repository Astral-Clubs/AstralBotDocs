# Как участвовать в проекте

Спасибо, что хотите улучшить документацию Astral Moderation. Принимаются исправления опечаток, уточнения, новые примеры и новые страницы. Для небольших правок не нужно ничего устанавливать: на каждой странице [сайта](https://docs.astralbs.xyz) есть ссылка **«Предложить правку этой страницы»**, она открывает редактор на GitHub и сама создает pull request.

Участвуя, вы соглашаетесь соблюдать [правила поведения](CODE_OF_CONDUCT.md).

## С чего начать

| Что хотите сделать | Что делать |
|---|---|
| Нашли опечатку или неточность | Нажмите «Предложить правку этой страницы» на сайте или [создайте задачу](https://github.com/Astral-Clubs/AstralBotDocs/issues/new/choose) |
| Хотите добавить пример или раздел | Сначала создайте задачу «Предложение по документации», чтобы согласовать место и объем |
| Хотите написать новую страницу | Тоже сначала задача. Так вы не потратите время на то, что уже пишет кто-то другой |
| Нашли проблему в самом боте | Это не к документации: напишите [боту](https://t.me/astralbsmodbot) |
| Нашли уязвимость | Не создавайте публичную задачу, прочитайте [SECURITY.md](SECURITY.md) |

## Как писать тексты

Все правила оформления и тона описаны в [руководстве по написанию](WRITING_GUIDE.md). Прочитайте его до первой своей страницы, оно короткое. Самое важное:

- Пишем для администратора чата без опыта программирования.
- Каждый пример шаблона проверен на боте.
- У страницы есть `description`, один заголовок `# ` и якоря у всех `##`.
- В коде сайта (конфиги, тема, скрипты, автоматизация) комментариев нет: код объясняют имена. Это проверяет `bun run check:comments`. На тексты страниц правило не распространяется.

## Локальная работа

Нужен [Bun](https://bun.sh) версии 1.4 или новее. Node.js и npm не используются.

```bash
git clone https://github.com/<ваш-аккаунт>/AstralBotDocs.git
cd AstralBotDocs
bun install
bun run dev
```

Сайт откроется на `http://localhost:5173` и обновляется при сохранении файла.

Перед отправкой запустите полную проверку:

```bash
bun run verify
```

Она делает четыре вещи: проверяет страницы по правилам руководства (`bun run check`), проверяет, что в коде нет комментариев (`bun run check:comments`), прогоняет тесты проверок и собирает сайт. Сборка падает на битой внутренней ссылке. Те же шаги выполняет CI, поэтому если локально зелено, в pull request тоже будет зелено.

## Процесс

1. **Форк и ветка.** Сделайте форк репозитория и создайте ветку от `main` с понятным именем: `fix/typo-in-variables`, `docs/button-examples`, `feat/new-reference-page`.
2. **Коммиты.** Пишем по-русски в стиле [Conventional Commits](https://www.conventionalcommits.org/ru/): `тип(область): описание`.

   | Тип | Когда |
   |---|---|
   | `docs` | Правка текста страниц |
   | `fix` | Исправление ошибки на сайте (сборка, тема, ссылки) |
   | `feat` | Новая возможность сайта |
   | `chore` | Зависимости, служебные файлы |
   | `ci` | Автоматизация |

   Примеры: `docs(templates): уточнить пример с кнопками`, `fix(theme): исправить переполнение таблицы на телефоне`.
3. **Pull request.** Откройте PR в `main` и заполните шаблон. Один PR — одна тема: исправление опечаток и новая страница лучше отдельными PR.
4. **Проверки.** PR сливается, только когда зеленые проверки CI и есть одобрение мейнтейнера.
5. **Ревью.** Мейнтейнер может попросить правки. Это нормально: цель — единый стиль и точность, а не оценка вас. Отвечать на замечания можно в самом PR.
6. **Слияние и публикация.** После слияния в `main` сайт публикуется автоматически на Cloudflare, обычно за несколько минут.

## Что делает PR хорошим

- Небольшой и сфокусированный.
- Объясняет, **зачем** правка, а не только что изменилось.
- Для примеров шаблонов: указано, что проверено на боте.
- Для изменений вида сайта: скриншот до и после, проверка на узком экране.

## Изменения, требующие согласования заранее

Откройте задачу до работы, если вы хотите:

- переставить разделы или поменять структуру меню;
- изменить тему, цвета или компоненты сайта;
- добавить зависимость;
- переписать страницу целиком.

## Использование ИИ-инструментов

Использовать ИИ при подготовке правок можно. Ответственность за результат остается на авторе PR: вы должны проверить текст и каждый пример на боте. PR с непроверенным ИИ-текстом, особенно с выдуманными свойствами и функциями языка шаблонов, будет отклонен. Если ИИ написал значительную часть, отметьте это в описании PR.

## Лицензии и авторство

Отправляя вклад, вы подтверждаете, что имеете право его передать, и соглашаетесь с тем, что он распространяется под лицензиями проекта:

- **Тексты документации** (`docs/`, кроме `docs/.vitepress` и `docs/public`) — [CC BY 4.0](LICENSE-CONTENT.txt).
- **Код сайта** (конфиги, тема, компоненты, скрипты, автоматизация) — [MIT](LICENSE).

Не добавляйте чужие тексты, изображения и шрифты без совместимой лицензии. Если материал взят из другого источника, укажите источник и лицензию в описании PR.
